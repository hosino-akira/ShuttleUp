# データベース概要

ShuttleUp は Spring Boot + Spring Data JPA を利用してデータベースを管理する。

エンティティを中心にドメインモデルを設計し、JPA による ORM を利用してデータベースを生成・管理する。

データベースは保守性・拡張性を重視し、将来的な機能追加にも対応できる構造を目指す。

---

# 設計方針

## 基本方針

- エンティティを中心にデータモデルを設計する。
- 必要になってから設計を追加する（YAGNI）の考え方を採用する。
- 将来利用する可能性だけを理由にテーブルやカラムは追加しない。
- 命名規則はプロジェクト全体で統一する。

---

## マスタデータとトランザクションデータ

本システムではデータを以下の2種類に分類する。

### マスタデータ（Master Data）

システム全体で利用する共通情報を管理する。

対象

- ExerciseCategory
- ExerciseType
- Exercise

マスタデータは管理目的で以下のカラムを保持する。

| カラム | 説明 |
|---------|------|
| displayOrder | 画面表示順 |
| enabled | 有効／無効フラグ |

これにより、データを削除することなく表示順の変更や無効化が可能となる。

---

### トランザクションデータ（Transaction Data）

ユーザーの日々の活動によって生成される実績データを管理する。

対象

- TrainingSession
- TrainingRecord
- Match
- Opponent

トランザクションデータには、原則として `displayOrder` や `enabled` のような管理用カラムは持たせず、業務データのみを保持する。

---

## 命名規則

### Java

- クラス名：PascalCase
- フィールド名：camelCase

### データベース

- テーブル名：snake_case（複数形）
- カラム名：snake_case

例

| Java | Database |
|------|----------|
| createdAt | created_at |
| trainingDate | training_date |
| avatarUrl | avatar_url |
